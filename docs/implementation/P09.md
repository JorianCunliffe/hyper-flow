## Implemented behavior

- Office outputs provides DOCX reports, editable PPTX slides and XLSX workbooks. The three initial layouts retain Overview, Accepted work, Communication evidence and Source notes. Administrator-created versions select the format, brand name, readable accent, Arial/Calibri and an optional bounded PNG logo. Templates and their embedded assets are immutable versions with project-only permitted use. Workflow templates remain separate visible flow definitions.
- Input preparation reads accepted operational records and permitted current Communications source messages through the additive evidence projection. Derived summaries, facts and extracted commitments are not report inputs. The deadline period is explicit and end-exclusive. Work states reflect the separately displayed observation time, not reconstructed historical states. Reports preserve obligation versions, source references, template version and input fingerprint. Incomplete/stale source responses block preparation; absent excerpts and bounded search coverage are disclosed.
- A designated input Ask approves the frozen snapshot. A durable transaction claims generation, and the file is saved with its byte fingerprint and an Office package integrity check. Duplicate requests reuse the same job. A separate file Ask requires explicit content/layout/formula review for the exact file fingerprint. A saved file can be recovered after the job receipt fails to save, without regeneration. An interrupted job with no intact file stays visible and requires a new job; it is not silently retried.
- Visible weekly report flows use a pinned template and a seven-day window ending at the run's creation time. They wait while the user approves inputs, generates and reviews the file in Office outputs. Reconciliation checks the reviewed file and integrity before completing the report step. Cancellation stops flow advancement; it does not erase the separately retained artifact.
- XLSX has an executive summary, accepted-work source rows and communication evidence. Counts use formula dependencies with deterministic cached results; dates and counts are typed. A disposable engine test changes an accepted record to fulfilled and verifies open/fulfilled counts recalculate, then restores the input. Source text remains literal text, never executable spreadsheet formulas.
- Optional Google export needs a distinct administrator grant to create report tabs in an editable connected spreadsheet, plus an exact-job export Ask. Existing project range grants do not grant tab creation. One atomic batch creates a stable new sheet ID and its snapshot cells. Reconciliation only reads. Existing, renamed or manually changed tabs are never overwritten. Current membership and grant revision are checked again immediately before dispatch. Provider observations remain separate from file generation and obligation fulfillment.
- Optional email handoff creates an unapproved visible flow that checks the reviewed artifact, then asks Communications to create a mailbox draft. The draft explicitly says it has no attachment; the user must attach the reviewed file manually before sending. This initial mailbox contract does not support automatic artifact attachments. No email send operation is introduced.

## Scope and operating limits

These are initial code-defined report layouts with versioned branding, not arbitrary uploaded Office-template editing. A job supports at most 100 operational records, 60 evidence excerpts, bounded source text and a 2.5 MB output file. Each server-only record is capped at 3.8 MB. The initial list returns at most 100 job summaries and registries retain up to 30 custom template versions. Lifecycle/pagination work is tracked in Phase 11. Files are immutable; editing a downloaded workbook does not synchronize back into operational records.

Google exports are reviewed static report snapshots, not live formula workbooks or general-purpose sheet editing. The XLSX download is the formula-bearing workbook. Google verifies the written range's current values; subsequent changes outside that range are not treated as report edits. An uncertain write remains held until read reconciliation succeeds. Disabling a grant cannot recall an already accepted provider request. A renamed/colliding tab is a visible conflict, with no automatic replacement or rollback.

No tenant brand was supplied, so built-in templates are unbranded. Logos remain bounded PNGs. The initial release CI caught two production advisories through an unused upstream image-size dependency. That parser has been removed from the installed dependency tree. The unchanged MIT-licensed PptxGenJS ESM distribution and types are now a private vendored runtime package with recorded upstream hashes, license and a minimal jszip dependency manifest. Its source does not import or embed image-size; optional filesystem/HTTPS imports use Node builtins. No audit gate was weakened. The vendored runtime must be reviewed on updates independently of registry advisories. See vendor/pptxgenjs-runtime/README.md and PROVENANCE.json.

The final production dependency audit reports zero vulnerabilities. The earlier full development audit is retained as historical evidence and still contains unrelated development-tool findings. This is not a claim that the entire development dependency tree is clean.
