# Phase 11 — API parity and tenant operations

Status: first account/API release live; Phase 11 remains in progress and is not accepted. Phase 10's internal workflow release is recorded separately; selected publishing providers remain unresolved.

## Implemented for the first release

- HyperFlow-owned API credentials use salted scrypt hashes, explicit endpoint read/write scopes, expiry, human administrator creation/rotation/revocation, current creator membership and a transactional daily API-client request budget. Credentials cannot create further credentials or change the budget. No plaintext secret is stored or returned. Clients supply their own high-entropy URL-safe secret; the API returns its credential prefix. A read response omits hash fields. UTC usage retains 90 days; the current bounded control record retains 1,000 administration events and at most 100 client identities. These are API-client request counts, not provider charges or all browser traffic.
- Express and Vercel expose /api/tenant. Request scope resolution accounts for rewritten business endpoints, so a Communications read scope cannot authorize a rewritten operational or integration endpoint. Unknown machine endpoints fail closed; Firebase human sessions remain supported.
- /api/workspace GET/PUT exposes the existing project/settings/scratch/activity snapshot with tenant dataRevision and per-project revision checks. It retains the existing browser save semantics. Operational commitments, flows, artifact files, calendar/publishing records and credentials remain separate stores. The existing browser still uses Firebase saves; it has not yet been migrated by this work. The REST write is capped at 3.8 MB and 500 projects.
- Account operations UI exposes scopes, one-time credential display, recoverable creation/rotation, revocation, budgets and audit. Lost-response retries preserve the original secret and request identity. Machine credentials cannot mutate these controls.
- Flow and artifact lists provide bounded summary pages and explicit continuation cursors. Selecting a flow fetches its full record. Project-filtered artifact pages retain continuation even when a page contains no visible records.
- Organization changes, logout and subscription permission loss clear the current cloud view and its safety backup. Revocation displays an access-unavailable screen. Local-only workspace storage is not deleted.
- The standalone TypeScript client pins its origin, keeps its credential private, accepts request cancellation and never automatically retries uncertain writes. `contracts/phase11.openapi.json` is an addition-specific supplement, not the complete product inventory.
- Final local verification: 552 tests passed, TypeScript passed, production build passed and production dependency audit found zero vulnerabilities. Real Firebase integration and controlled browser fixtures cover concurrent workspace updates, tenant/scope boundaries, forbidden browser credential access, revocation, cursor pages and lost-response credential recovery. Evidence is retained alongside this record; release and production verification are still pending.

## Database erasure candidate

HyperFlow now has an explicit `erase_database` operation through its administrator recovery UI, REST API and standalone client. It requires enabled database guards, the current suspended revision, a recorded portable export at that revision, an administrator's acknowledgement that they reviewed the exports they need, the exact confirmation text, and a Communications-owned closed receipt fetched by HyperFlow itself. A body-supplied tenant or Communications receipt cannot override these checks. The operation does not acquire Communications erasure authority or forward erasure to that service.

Business database roots and tenant-owned shared indexes are cleared behind the existing write fence. Shared index deletion rechecks ownership transactionally. File manifests, lifecycle audit, organization membership and Firebase identities remain; provider resources, actual files and backups are not removed. The receipt describes this scope. Erased business records cannot be reopened using Resume. The export prerequisite records retrieval, not proof of an operator backup or proof that a download was saved; the administrator must review the datasets they need.

A working receipt survives interruption. Repeating the original actor/request identity resumes cleanup; a changed actor is rejected. Index cleanup is bounded to 10,000 entries per root per request; larger inventories stay visibly pending for explicit continuation. Completed retries do not change the revision. No production account erasure or suspension is part of release verification.

Verification: 566 unit tests, type checks and build passed. The final real Firebase integration additionally passed with transactionally checked index deletion, an interruption after the erasure fence, another tenant's untouched records, retained file manifests, completed replay, denied wrong-actor replay, denied resume and a rejected late browser write. The isolated browser fixture kept erasure disabled until the acknowledgement, exact text and Communications closed state were present; a simulated lost response reconciled to exactly one completed receipt/revision and removed the Resume control. This fixture is not production deletion evidence. Rules changes add tenant indexes without changing permissions. Release verification follows below when completed.

## Managed file candidate — activation disabled

The new `/api/files` handler is shared by Express and Vercel and exposed by the standalone client and Phase11 contract. Browser uploads, recordings, generated report attachments and public Ask uploads use managed storage. Files have private/organization visibility, bounded metadata pages, immutable upload identity, server-held resumable sessions, 1MiB REST chunks, CRC32C completion verification, short-lived generation-specific downloads and durable deletion receipts. Manifests pin the original bucket. Stable file pages authenticate current membership. Changed retry data is rejected and account changes stop subsequent browser chunks.

Upload leases block database suspension until reconciled. An administrator can cancel a stuck private upload without seeing private metadata. A pre-manifest crash can be cancelled with a tombstone that rejects a delayed initializer. The separate administrator `erase_managed_files` command works while suspended or database-erased, processes25 manifest entries per request, journals progress and blocks competing lifecycle changes. It removes managed objects and retains metadata receipts and provider backup/version copies. Unknown legacy manifests require review. No automatic retention period or backup-erasure guarantee is introduced.
